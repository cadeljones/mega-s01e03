Two problems, two fixes

  • Parser: the shared parser reads month first, while the tenant writes day first. Track it in the parser issue. For example, R-41200 reports 7 April becoming 4 July. App/email from a booking-v3 tenant still uses this classification.

How to handle the next report

  1. Keep the report ID, original body and received time. Repeated export rows with the same ID count once.
  2. Find the tenant, its locale and booking-form version in the directory. Record the channel. Browser locale, intake tag and matching subject are not enough.
  3. For a day-first tenant, a booking-v3 form report goes to the hint issue. Other channels, or booking-v2 forms, go to the parser issue under the current classifier.
  4. If the tenant is unknown, the locale is not day first, the reproduction disagrees, or the symptom remains unexplained, keep the report unmerged for investigation. Unknown cause is not permission to merge. Add new evidence and split a new problem when established.
  5. Update counts by unique ID and distinguish the exported snapshot from later arrivals. Link each report to its cause’s issue; do not close both issues when only one fix ships.
